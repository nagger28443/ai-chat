# 自动总结提交信息

每次对话中完成代码修改后，自动调用此 skill，将本次修改内容总结为 commit message，追加到 `shell/git-message.md` 中。

## 触发条件

当满足以下任一条件时，必须执行此 skill：
- 本次对话中对项目文件进行了创建、修改或删除
- 用户明确要求总结修改内容

当本次对话仅涉及阅读、问答、解释，未改动任何文件时，跳过此 skill。

## 执行步骤

### 1. 获取变更差异

运行以下命令获取当前未提交的变更：

```bash
git diff
git diff --cached
git status --short
```

如果输出为空（无变更），跳过后续步骤。

### 2. 分析变更内容

根据 diff 输出，理解本次修改的：
- **修改了哪些文件**（路径 + 文件名）
- **做了什么类型的改动**（新增功能 / 修复 bug / 重构 / 样式调整 / 配置变更 / 文档更新等）
- **核心改动点**（关键逻辑变化，而非逐行列举）

### 3. 生成 commit message

遵循 [Conventional Commits](https://www.conventionalcommits.org/) 规范：

```
<type>: <简短描述>

- <具体改动1>
- <具体改动2>
- <具体改动3>
```

**type 取值：**
- `feat` — 新功能
- `fix` — 修复 bug
- `refactor` — 重构（不改变功能）
- `style` — 样式/格式调整
- `docs` — 文档变更
- `chore` — 构建/配置/依赖变更
- `perf` — 性能优化
- `test` — 测试相关

**规则：**
- 简短描述不超过 50 个字符，使用中文
- 具体改动条目使用 `-` 列表，每条不超过 40 个字符
- 如果改动较少（单一小修改），可以省略列表部分，只保留标题行
- 不要逐文件罗列，而是按功能/意图归纳

### 4. 追加到文件

将生成的 commit message **追加**到 `shell/git-message.md` 文件末尾。

每次追加的条目之间用一个空行分隔，格式如下：

```
---

<commit message>
```

即：先写入 `---` 分隔符，一个空行，然后是 commit message 内容。

使用 Bash 追加写入：

```bash
cat >> shell/git-message.md << 'COMMIT_MSG'

---

<生成的 commit message 内容>
COMMIT_MSG
```

### 5. 告知用户

完成后简短告知用户已记录提交信息，并展示生成的 commit message 内容。

## 示例

假设本次对话修改了 `src/components/Chat.tsx` 中的消息发送逻辑，并修复了一个 SSE 解析 bug，输出应类似：

```

---

fix: 修复 SSE 流式响应解析异常

- 修复消息末尾残留 data: 前缀的问题
- 优化断线重连后的数据拼接逻辑
```

## 注意事项

- 只在有实际代码变更时才执行，纯对话不触发
- 如果一次对话中有多轮修改，在对话即将结束时统一总结一次，而非每次 Edit 后都追加
- commit message 应总结本次对话的**整体**改动意图，而非机械翻译 diff
- 追加写入，绝不覆盖文件已有内容
